## 基本概念
首先区分三种记忆：
1. LLM模型记忆：预训练知识，微调结果、模型编辑等，信息存在参数中
2. 上下文/工作记忆：当前prompt,KV cache,scratchpad，近期观察和任务状态
3. Agent长期记忆：跨任务、跨会话持久化的事实、技能和用户信息。

AI Agent记忆系统研究全景图

|研究方向|核心问题|代表作|
|---|---|---|
|工作记忆与分层管理|上下文窗口太小记不下|MemGPT,MenoryBank|
|情景与语义记忆|记住具体经历与抽象事实|Generative Agents|
|反思记忆与经验学习|从成功或失败中总结教训并复用|Reflexion,ExpeL|
|程序性记忆|把学到的技能和操作流程固化|Voyager|
|记忆检索与主动调度|记忆太多如何精准找到最有用一条|MIRIX,HyMem|
|压缩与潜在记忆|能否将海量记忆压缩为更小的数据包|LongMem,Titans|
|多模态与多Agent共享|文字图像，多个Agent共用记忆|MIRIX、eMEM|

总体上，最值得关注的转变是：Agent Memory正从数据库组建变成一种可学习的控制系统。最新综述通常用"形式-功能-动态"三维框架描述它。

## KV Cache/上下文压缩
上下文是输入给模型的所有文本，而KV Cache是模型在处理这些文本时生成的、为了高效生成后续内容而缓存的中间计算结果。

上下文包含系统提示词，历史对话，用户当前问题，通过RAG检索到的相关文档片段，工具调用的结果等内容。

当模型在“阅读”上述上下文时，为了理解每个词在整段话中的含义，它内部的多头注意力机制需要做大量计算。其中最关键的计算，就是为每个Token生成一对向量：

- K（Key，键）：可以理解为这个Token的“索引标签”，用于和其他Token匹配。
- V（Value，值）：可以理解为这个Token的“内容本身”，包含它的语义信息。

KV Cache就是把这些计算好的K和V向量，在显存中暂时存储下来。

### 什么是KV Cache
当LLM生成文本时，特别是处理长上下文或长对话时，它采用一种自回归方式，为了生成下一个字，模型需要回顾之前处理过的所有字词。

- K（Key）和 V（Value）：这是 Transformer 模型注意力机制中的关键向量。你可以把它们理解为模型为每个输入 token（词或子词）生成的“索引”（Key）和“内容摘要”（Value）。

- Cache（缓存）：为了避免每次生成新字时都重新计算前面所有 token 的 K 和 V（这计算量巨大），模型会把这部分计算结果缓存下来，放在 GPU 显存里，下次直接用。

Cache 的大小是随着输入长度和对话轮次线性增长的。处理一篇长文档或几十轮对话，KV Cache 就能轻松占据几十 GB 的显存。这就是为什么上下文窗口越大，对算力和显存的要求就越高。
### 上下文压缩
上下文压缩是一个统称，指所有旨在减少输入给 LLM 的上下文信息量，同时尽量保留关键信息的技术集合。这些技术最终的目的，几乎都是为了减小 KV Cache 的体积，或者在 KV Cache 撑爆显存之前，对它进行精简。

主要有两种方式：
1. 输入层压缩(在进入模型前)，做法包括直接精简prompt,摘要，RAG检索，记忆抽取(从对话中只提取关键事实)等方式，从根本上减少进入模型的token数量。
2. 模型层压缩(在模型内部)：精简KV cache本身，不改变输入但让每条KV占据更小的空间，或者让总条数变小。

### 主要研究路线
#### PagedAttention 减少碎片，不减少信息
[vLLM/PagedAttention](https://arxiv.org/abs/2309.06180) 把 KV Cache 切分为固定大小的block，逻辑上连续的序列可以映射到不连续的 GPU 物理块，类似操作系统的虚拟内存分页。
它主要解决：
  - 不同请求长度不同造成的显存碎片；
  - 预留最大长度导致的显存浪费；
  - beam search 或多个分支之间共享前缀；
  - 请求动态加入和结束时的显存分配。

PagedAttention没有减少每个token的KV大小，也没有判断哪些token可以删除，因此它是后续研究的基础设施，而不是完整的KV压缩算法。
